## 3. 전략 규칙 — `lib/strategy/mean-reversion.ts` (순수 함수)

일봉 종가 계열의 마지막 값은 **오늘의 실시간 가격**이다(§4.3).

- **지표**: SMA(n) 단순 이동평균. RSI(2)·ATR(14)는 Wilder 평활(백테스트와 같은 식).
- **진입 신호** — 다음이 모두 참:
  1. 가격 > SMA200
  2. RSI(2) < `mr_rsi_entry` (기본 10)
  3. `mr_regime_filter`가 켜져 있으면 SPY 가격 > SPY SMA200
  4. 그 종목에 열린 포지션이 없음 (물타기 없음)
  5. **오늘(ET) 판 종목이 아님** — 백테스트는 청산 다음 날부터 재진입한다. 재난 손절로 판 종목을 같은 날
     판단 틱이 다시 사는 것을 막고, 판단 재시도의 멱등도 겸한다(§2.4.1). 조회 실패 시 그날 진입 없음(`mr_data_error`).
- **우선순위**: 신호 여러 개가 예산보다 많으면 **RSI(2) 오름차순**으로 산다.
- **청산** — 먼저 오는 것으로 **전량**:
  1. **재난 손절**: 가격 ≤ `positions.stop_price` (= 진입가 − `mr_stop_atr` × 진입 전일까지의
     ATR(14), 기본 5). `mr_stop_atr = 0`이면 없음. **매 틱** 확인. 손절가는 **진입 시점에 고정**된다 —
     `mr_stop_atr`를 나중에 0으로 바꿔도 이미 연 포지션의 손절은 남는다(새 포지션·빈 손절가 채우기에만 적용).
  2. **MA5 회복**: 가격 > SMA5. **판단 틱에서만**, 진입 당일 제외.
  3. **보유 기간**: 진입일 이후 거래일 수 ≥ `mr_max_hold_days`(기본 10). 거래일 수는 §4.3의 "오늘
     봉까지 합친 일봉 계열"에서 **진입일보다 뒤인 서로 다른 날짜의 개수**다 — 오늘은 FMP가 행을
     주든 합성 봉이든 정확히 한 번 센다. 달력 로직이 필요 없다. **판단 틱에서만**.
- SMA 기간(200·5)은 상수다. 규칙의 정체성이라 설정으로 뺄 이유가 없다.
- **판단 불가는 신호 없음이다**: 일봉이 200개 미만(최근 상장)이면 그 종목은 신호가 없다. SPY 일봉이나
  실시간 가격을 못 구하면(일봉만 있고 실시간 가격이 없으면 어제 종가로 국면을 보게 되므로 이것도 실패다) `mr_regime_filter`가 켜진 동안 **그날 진입 전체를 하지 않는다**(fail-closed,
  `mr_data_error`). 청산은 종목별 데이터로 판단하므로 SPY 실패가 청산을 막지 않는다(원칙 7).

## 4. 실행 흐름 — `api/cron/execute.ts`

### 4.1 틱의 두 단계

| 단계 | 언제 | 하는 일 |
|---|---|---|
| 위험 단계 | 모든 틱(기본 10분) | 킬 스위치, 일일 손실·거래 한도(§4.5), 재난 손절, 비어 있는 `stop_price` 채우기(§4.2), 가격 조회 실패 처리 |
| 판단 단계 | 장 마감 20분 전 창의 **첫 틱**, 하루 1회 | 규칙 청산(MA5·기간), 진입 신호 계산·우선순위·주문 |

- 창은 core `minutesUntilUsMarketClose`/`usMarketCloseMinute`로 잡는다 — 반일장(13:00 마감)은
  12:40부터다. 창 길이 20분은 상수.
- **하루 1회 보장**: 판단 단계를 끝낸 런은 `cron_runs.summary.decisionPhase = 'done'`을 남긴다.
  같은 ET 날짜에 그 행이 있으면 다시 하지 않는다. 런이 중간에 죽으면 행이 없으니 다음 틱이
  재시도하고, 이미 산 종목은 "열린 포지션 있음"·진행 중 매수 가드로, 판 종목은 "오늘 판 종목"으로 걸러져 중복되지 않는다.
  **`done`을 남기지 않는 경우**: 실행 시한 초과, 마감 임박 중단(아래), 이 런에 `mr_data_error`가 하나라도 있음 —
  일시적 FMP 장애로 그날 판단을 잃지 않도록 창의 다음 틱이 재시도한다.
- **마감 임박 중단**: 판단 단계는 주문 직전마다 마감까지 남은 시간을 다시 보고 1분 이하면 남은 주문을 내지 않는다
  (`summary.closeCutoffHit`). 재시도 틱(:57)이 FMP 지연으로 길어져 16시 뒤 시장가 주문이 나가는 것을 막는다.
  semi_auto 승인 요청의 만료는 `min(15분, 마감)`이고, 승인 API는 정규장이 아니면 거부한다.
- `execute_interval_min` 허용값을 **5/10**으로 줄인다. 게이트가 `(분 − 7) mod 간격`이라 창(20분)
  안의 틱 수가 간격마다 다르다 — 5분 4틱, 10분 2틱(:47·:57), 15·20분 1틱, 30·60분 0틱.
  한 틱뿐이면 그 틱이 락 경합(`skipped`)이나 일시 장애로 판단을 못 한 날은 **그날 판단이 통째로
  사라진다.** 재시도 틱이 최소 하나 있어야 한다. 저장값이 범위 밖이면 기존 파서가 기본값(10)으로
  떨어뜨린다.
- 판단 틱이 아니고 열린 포지션도 없으면 **감사 행 없이** 반환한다(인터벌 게이트와 같은 이유 —
  하루 50여 행의 잡음). execute가 살아 있는지는 §6의 execute 전용 검사가 판단 행으로 확인한다.

### 4.2 주문 경로는 그대로

dry_run 장부 트랜잭션, semi_auto 대기 주문, auto 브로커 주문·`order_tracking`·부분 체결·거절
처리는 **바꾸지 않는다.** 바뀌는 것은 그 경로에 들어가는 판단(무엇을, 얼마나)뿐이다.

- **비중**: `planEntry`(종목 한도 ∩ 총 노출 한도 ∩ 현금)의 전액, `fraction = 1`. 사이징 게이트는
  호출하지 않는다. 청산은 전량(`planExit` `hard: true`).
- 매도 in-flight 가드, 대기 주문 가드, `getSellableQuantity` 클램프, 킬 스위치 재확인은 유지.
- **매수 in-flight 가드(`hasPendingBuy`)도 유지한다 — 멱등의 한 축이다.** 판단 단계가 주문을 낸 뒤
  `finishCronRun` 전에 죽으면 다음 틱이 판단을 재시도한다. `dry_run`은 포지션이 이미 있어 걸러지지만
  `auto`는 체결 전(`submitted`)이라 포지션이 아직 없다. 이 가드가 없으면 같은 종목을 두 번 산다.
- **`positions.stop_price`는 포지션을 여는 모든 경로가 채운다** — execute 두 곳, semi_auto 승인
  (`api/approve/[id].ts`), reconcile 지연 체결 복구(`lib/db/recovery.ts`). 뒤의 두 경로는 ATR 맥락이
  없으므로 `NULL`로 열고, execute가 **매 틱** `stop_price IS NULL`인 열린 포지션에 대해 그 종목 일봉을
  받아 계산해 채운다. 비어 있는 동안 재난 손절이 조용히 꺼져 있으면 안 되기 때문이다(드물어서 비용은 작다).
- 일일 손실 한도의 `forceFullExit`: 판단 불가(일봉 조회 실패) 포지션은 실시간 가격으로 청산,
  가격도 없으면 기존 `skipped_no_price` + 메일. 규칙상 청산이 이미 전량이므로 "비중 상향"은 의미가 없다.
- 손절가 채우기가 실패하면(일봉 없음) `stop_backfill_failed` 결정 행 + 종목당 하루 1회 메일 — 재난 손절이 꺼진
  상태가 조용하면 안 된다.
- 한 런 안의 예산: semi_auto 승인 요청과 auto 미체결 매수도 계획 금액만큼 현금·노출에서 차감한다 — 한 런에서
  여러 종목을 사므로, 차감하지 않으면 요청마다 같은 잔고로 사이징된다.

### 4.3 데이터

- 일봉: FMP `getBars({ timeframe: '1Day', from: 400일 전 })`, 판단 틱에만 (관심종목 ∪ 보유 종목 ∪ SPY).
- 오늘 봉: 마지막 봉 날짜가 오늘(ET)이면 종가를 실시간 가격으로 바꾸고 고가·저가를 넓힌다.
  아니면 실시간 가격으로 합성 봉을 붙인다. 공급자(`fmp-market-data-provider.ts` `getDailyBars`)는
  EOD 계열에 오늘 행이 없으면 **quote로 만든 오늘 봉을 이미 붙여** 돌려준다 — 그래서 보통은 첫 경우다.
  두 번째 경우(quote 실패)도 처리한다.
  실호출 확인(2026-09-24 08:52 ET, 장 전, 18종목): 전 종목 276봉, 마지막 봉이 오늘 날짜로 붙어 있었다.
  **장 전 quote는 `price` = 전일 종가, `previousClose` = 그 전날 종가**다 — 그래서 합성된 오늘 봉은
  전일 종가의 복제다. execute는 세션 게이트 뒤에서만 돌고 판단은 마감 20분 전이라 영향이 없지만, 장 밖에서
  이 경로로 "오늘"을 판단하는 코드를 새로 만들면 안 된다.
- 실시간 가격: 기존 `fetchLivePrice`.
- 재난 손절은 `positions.stop_price`만 보므로 **일봉 조회가 실패해도 작동한다.**

### 4.4 dry_run 비용

새 설정 `dry_run_cost_bps`(기본 **10**, 0~100)를 모의 체결가에 반영한다 — 매수 `가격 × (1 + c)`,
매도 `가격 × (1 − c)`. 거래당 기대값이 ±0.2% 수준에서는 왕복 비용이 부호를 바꿀 수 있어서다.
auto·semi_auto는 브로커 체결가를 그대로 쓴다. dry_run의 `trades.price`는 비용이 반영된 값이라
대시보드 체결가도 그 값이다 — 현금 원장(`getDryRunCashFlowUsd`)과 실현 손익이 같은 가격에서 나와야
어긋나지 않는다.

### 4.5 일일 손실 차단기 — 미실현 손익을 "오늘 변동분"으로 바꾼다

현행 차단기의 미실현 항은 **진입가 대비 누적 손익**이다. 장중 전략에서는 포지션이 당일 청산돼
둘이 같았지만, 평균 4거래일을 들고 가는 이 전략에서는 다르다 — −10% 눌린 $5,000 포지션 하나가
기본 한도 $500을 채우고, 그 포지션이 회복할 때까지 **며칠 동안 모든 진입을 막는다.** 이 전략이
신호를 내는 날(눌림)이 정확히 그런 날이다.

포트폴리오 시뮬레이션(5슬롯, 누적 미실현 기준 차단):

| 한도(자본 대비) | 2015-19 막힌 신호 / 연수익 | 2020-22 | 2023-26 | 2023-26 MDD |
|---|---|---|---|---|
| 없음 | 0 / 5.4% | 0 / 13.0% | 0 / 19.6% | 30.4% |
| **2% ($500 / $25k, 현행 기본)** | 94 / 4.3% | 62 / 10.9% | **366 / 12.7%** | 27.5% |
| 5% | 9 / 5.1% | 11 / 13.0% | 143 / 18.3% | 31.6% |

2%는 수익의 1/3을 버리고 MDD는 거의 못 줄인다. 한도를 올리는 것만으로는 이름("일일")과 계산이
계속 어긋나므로 **정의를 고친다**: 미실현 항 = 보유 포지션의 **오늘 변동분**
(`수량 × (현재가 − 기준가)`, 기준가 = 오늘 진입이면 진입가, 아니면 전일 종가). 전일 종가는 FMP
quote의 `previousClose`로 받는다(`fetchLivePriceDetail` 확장 — 응답에 필드가 있음을 실호출로 확인). 실현 항은 그대로 오늘 실현 손익이다.

- `previousClose`를 못 받은 포지션은 진입가를 기준가로 쓴다 — 현행 차단기의 "빼지 않고 대체한다"
  원칙(빠진 포지션은 손실을 과소 집계해 차단을 늦춘다)을 그대로 따른다.
- 기준가에서 25% 넘게 벗어난 시세는 깨진 틱일 수 있다. **손실 쪽이면 그대로 합산하고 이익 쪽만 버린다** — 깨진
  급등 틱이 손실을 가리면 안 되고, 진짜 폭락(손절이 즉시 못 도는 `mr_stop_atr = 0`·semi_auto)은 차단기에 잡혀야 한다.
  차단기는 진입만 막으므로 손실 쪽으로 틀리는 비용이 작다.
- 차단 시 동작(진입만 막음, `forceFullExit`)은 바꾸지 않는다.
- **메일은 하루 1회**로 줄인다. 지금은 차단된 동안 매 틱 `notifyError`를 보내는데, 여러 날 보유하는
  전략에서는 그대로 두면 몇 시간씩 10분마다 쌓인다.
- `max_daily_loss_usd` 기본 500은 유지한다. 오늘 변동분 기준 $500은 $25k 자본의 2% 일일 손실이다.

## 5. AI 리뷰 (기록 전용) — `api/cron/review.ts`, `lib/analysis/entry-review.ts`

**주문에 영향을 주지 않는다. 주문도 리뷰를 기다리지 않는다.**

- **대상**: 오늘(ET) 판단 단계가 남긴 **신호 결정 전부** — 체결된 것(`mr_buy`)과 예산·한도로
  못 산 것(`mr_skip_*`)을 모두 포함한다. 못 산 신호도 전진 수익률로 평가할 수 있고, AI가 가치를
  내는지 재려면 표본이 많아야 한다.
- **스케줄**: `*/10 16-21 * * 1-5`(UTC). 반일장 판단(ET 12:40, UTC 16:40)부터 정규 마감 뒤까지
  덮는다. 처리할 신호가 없으면 감사 행 없이 반환.
- **입력**: 그 종목의 기술(**1Day**)·뉴스·펀더멘털 분석. 오늘 이미 저장된 같은 종류 분석이 있으면
  재사용하고, 없으면 기존 러너로 실행해 `analysis_results`에 저장한다(대시보드 분석 화면이 이걸 쓴다).
  신호 맥락(RSI2, MA200·MA5 대비 거리, 1/3/5일 등락, SPY 국면)을 함께 준다.
- **질문**: "규칙이 단기 눌림을 샀다. 이 하락은 노이즈·과잉반응인가, 정보(악재·실적·가이던스·
  규제·종목 특정 충격)에 의한 것인가?" 출력:
  `{ "fraction": 0~1, "dropCause": "noise|news|earnings|macro|unknown", "confidence": 0~100, "reason": "…" }`
  — `fraction`은 "AI가 정했다면 낼 비중"(0 = 거부). 가설은 **악재성 하락 거르기**다: 눌림매수의
  큰 실패는 진짜 악재로 떨어진 경우이고 가격 규칙은 그것을 구분하지 못한다.
- **저장**: `trade_audit` — `kind = 'entry_review'`, `fraction`·`confidence` 컬럼, `raw_response`에
  `dropCause`, `correlation_id = review-<ET 날짜>-<종목>`(멱등 키 — 이 값이 있으면 건너뜀). 키가 결정 행 id가
  아니라 종목·날짜인 이유: 판단이 재시도 틱에서 다시 돌면 같은 신호가 새 행으로 또 남는다. 오류(판독 불가·예외)도
  같은 키로 행을 남겨 매 틱 재시도하지 않는다. 대상은 action이 아니라 `detail.mr.signal = true`로 고른다 —
  `auto`에서는 주문 결과가 action을 덮어쓴다(`order_submitted` 등). 정규장 마감 뒤 실행된 리뷰는 결정 행에
  `afterClose: true`를 남긴다(마감 뒤 뉴스가 섞였을 수 있다).
- **모델**: `analysis_model_config`의 `trade_gate` 행을 `entry_review`로 이름만 바꾼다(마이그레이션).
  `options`·`congress` 행은 삭제. 호출은 게이트와 같은 core `callAnalysisAi`(`tier: ANALYSIS_TIER`,
  reasoning off)이고, 기술 분석 `1Day`도 pro tier라 게이팅되지 않는다.
- **타입 넓히기**: `insertTradeAudit`의 `kind`(`'entry' | 'exit'`)에 `'entry_review'`, `CronType`에
  `'review'`를 더한다. 제거되는 분석 크론 타입은 과거 `cron_runs` 행 표시 때문에 유니온에 남긴다.
- 프롬프트 렌더링(`renderAnalysisBody` 등)은 `trade-gate.ts`의 것을 옮겨 재사용하고, 사이징 게이트
  본체(`runTradeGate`와 그 프롬프트)는 삭제한다.
- **승격 조건**: 신호 30건 이상 쌓이면 `fraction = 0`(거부)과 나머지의 규칙 수익률을 기준선과 나란히
  비교한다(원칙 13). 차이가 있을 때만 거부권·비중으로 승격하는 별도 설계를 한다.
- 호출량: 신호당 LLM 4회(분석 3 + 리뷰 1), 백테스트 기준 하루 평균 0.5건 → 종전(하루 약 92회)의 수% 수준.

## 8. 원칙 선언

- **원칙 7**: 조이는 것은 진입뿐이다(RSI·국면·예산). 재난 손절과 한도 차단기는 매 틱 돈다. MA5·기간
  청산이 판단 틱에만 도는 것은 차단이 아니라 규칙의 정의(종가 기준)다 — 백테스트가 그렇게 검증됐다.
- **원칙 11**: 예상 신호율은 18종목 하루 약 0.5건이고, SPY가 MA200 아래인 기간에는 0이 정상이다.
  그 상태는 `mr_regime_off`로 기록된다.
- **원칙 12·13**: 임계는 분포 꼬리가 아니라 **통과 쪽 전진 수익률 vs 기준선**으로 정했고(§2.2),
  이웃 파라미터가 모두 같은 부호다.

const sma = (a, n) => { const o = new Array(a.length).fill(null); let s = 0; for (let i = 0; i < a.length; i++) { s += a[i]; if (i >= n) s -= a[i - n]; if (i >= n - 1) o[i] = s / n; } return o; };
function wilder(v, n) { const o = new Array(v.length).fill(null); let s = 0; for (let i = 0; i < v.length; i++) { if (i < n) { s += v[i]; if (i === n - 1) o[i] = s / n; } else o[i] = (o[i - 1] * (n - 1) + v[i]) / n; } return o; }
const rsi = (c, n) => { const ch = c.map((x, i) => i ? x - c[i - 1] : 0); const g = wilder(ch.map(x => Math.max(x, 0)), n), l = wilder(ch.map(x => Math.max(-x, 0)), n); return g.map((v, i) => v == null ? null : l[i] === 0 ? 100 : 100 - 100 / (1 + v / l[i])); };
// bars: FMP EOD rows (date, open, high, low, close) sorted asc; spyUp: Map(date -> SPY close > SMA200)
function prep(raw, spyUp) {
  const c = raw.map(b => b.close), m5 = sma(c, 5), m200 = sma(c, 200), r2 = rsi(c, 2);
  const tr = raw.map((b, i) => i ? Math.max(b.high - b.low, Math.abs(b.high - raw[i - 1].close), Math.abs(b.low - raw[i - 1].close)) : b.high - b.low);
  const atr = wilder(tr, 14);
  return raw.map((b, i) => ({ ...b, m5: m5[i], m200: m200[i], r2: r2[i], atr: atr[i], spyUp: spyUp.get(b.date) ?? null }));
}
const signal = b => b.m200 != null && b.close > b.m200 && b.r2 != null && b.r2 < 10 && b.spyUp === true;
// decide + fill at signal-day close; exit at close when close > SMA5 or after 10 days; 5×ATR stop intrabar (gap -> open)
function sim(bars, cost = 0.001, stopAtr = 5) {
  const out = []; let i = 0;
  while (i < bars.length - 2) {
    const b = bars[i]; if (!signal(b)) { i++; continue; }
    const entry = b.close, stop = stopAtr ? entry - stopAtr * b.atr : -Infinity; let px = null, j = i + 1;
    for (; j < bars.length; j++) { const x = bars[j];
      if (x.open <= stop) { px = x.open; break; } if (x.low <= stop) { px = stop; break; }
      if (x.m5 != null && x.close > x.m5) { px = x.close; break; } if (j - i >= 10) { px = x.close; break; } }
    if (px == null) break; out.push({ date: b.date, ret: px / entry - 1 - 2 * cost, days: j - i }); i = j + 1;
  }
  return out;
}
